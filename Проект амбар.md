### Проектная основа  

Будем делать PWA offline-first

Это обычный сайт, но он:
1. открывается в браузере;
2. может устанавливаться как приложение;
3. работает без интернета;
4. сохраняет черновики локально;
5. при появлении сети синхронизирует данные с сервером.

Service Worker - чтобы само приложение открывалось без интернета
IndexedDB - чтобы хранить отчеты, фото и черновики локально
Sync Queue - очередь отправки на сервер
Backend API - сервер принимает готовые отчеты
Document Generator - создает PDF/DOCX по макету
(?) Background Sync API - позволяет отложить отправку и выполнить её, когда появится стабильное соединение

Локальное хранение:
- report_id
- статус: draft / ready / synced / error
- данные формы
- фото
- время создания
- пользователь
- версия шаблона документа

Сжатие фото на клиенте, например до 1280–1920 px по ширине.

Frontend на Vue:
- Vue 3 - интерфейс
- Vite - сборка проекта
- Pinia - состояние приложения
- Vue Router - несколько страниц
- IndexedDB/idb - локальная база
- Service Worker / Workbox - offline

Логика:
1. Web-приложение загружается
2. Скачивает актуальный шаблон документа
3. Пользователь заполняет отчет и добавляет фото
4. Все сохраняется локально
5. Документ генерируется локально
6. Пользователь сразу скачивает PDF/DOCX
7. Когда появляется интернет отчет, фото и готовый документ уходят на сервер

### Интерфейс 

Что будет в приложении:
- Выбор амбара
- Выбор завода
- Выбор продукта
- Дата
- Партия / номер поставки
- Показатели качества
- Фото продукта
- Подпись / ФИО ответственного

Часть полей — выпадающие списки.  
Часть — текст/числа.  
Фото — через камеру или загрузку файла.
# Примечание об актуальной архитектуре

Черновой offline-first план ниже оставлен как история проектирования. Текущая реализация хранит
данные только на сервере в SQLite и работает с ними через HTTP API. Актуальный запуск и структура
описаны в `amb_ar/README.md`.
